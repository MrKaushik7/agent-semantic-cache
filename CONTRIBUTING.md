# Contributing

Thank you for helping improve Semantic Cache. This is a learning-first project, so focused,
well-explained contributions are preferred over large speculative changes.

## Before starting

- Search existing issues before opening a new one.
- Use the bug or feature form so the report contains enough context to evaluate.
- For a substantial or cross-cutting change, open an issue before investing in implementation.
- Never report a suspected vulnerability in a public issue. Follow [SECURITY.md](SECURITY.md).

By participating, you agree to follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Development workflow

1. Fork the repository and create a narrowly scoped branch.
2. Follow the setup and test commands in [README.md](README.md#development).
3. Add or update tests and documentation when behavior changes.
4. Run the relevant checks locally.
5. Open a pull request explaining why the change is needed and how it was verified.

Keep unrelated refactors out of the same pull request. Generated artifacts, credentials,
personal data, and production logs do not belong in commits or issue reports.

## Third-party material

Before copying or adapting code, documentation, data, or media, verify that its license is
compatible with this project's Apache-2.0 license and record the required information described
in [ATTRIBUTION.md](ATTRIBUTION.md).

Maintainers may close contributions that are unsafe, out of scope, insufficiently evidenced, or
incompatible with the project's license and direction.
